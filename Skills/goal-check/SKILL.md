# Goal Check

エージェントが現在どう理解しているかを示し、ユーザーとの認識のずれを見つける。

スキル名での呼び出しや、条件を確認する明示的な依頼に応じて使う。「ゴール」という言葉が出ただけで起動したり、毎回の作業開始時に定型の確認を挟んだりしない。

## 確認する情報

- 概念の定義と判断基準は [OperatingPrinciples](../../OperatingPrinciples.md#ゴール・目標・制約条件) を参照する。相対リンクは、このスキルの実体の所在を基準に解決する。
- 標準では現在のチャットで扱う依頼を対象とする。別の案件が指定された場合は、その対象を確認する。
- 会話と依頼に直接関係する文書を照合する。登録済みのゴールがあり、読み取り機能を利用できる場合は、その内容も確認する。
- 関係のない案件へ調査を広げない。参照できない情報は未確認として扱い、ユーザーの判断が必要な点と、資料や機能を利用できない点を区別する。

## 整理と照合

1. ゴール・必須目標・努力目標・制約条件を抽出し、それぞれの根拠を確認する。ユーザーが後から訂正した内容も反映し、明示・合意された条件と推測・未確定事項を区別する。
2. 現在の作業や予定している作業を条件と照合する。目標の勝手な追加、必須と努力の取り違え、制約違反、不要な範囲拡大がないかを確認する。
3. 必須目標と必要な検証の達成状況から、完了に必要な残作業を整理する。努力目標の未達や、採用されていない改善案を残作業に混ぜない。
4. 現在の理解を先に示し、作業判断に影響するずれや不明点がある場合だけ質問する。既に分かっている条件は聞き直さない。回答を受けたら、影響する理解・残作業・確認事項を更新する。

一覧を埋めるために目標や制約を作り足さない。エージェントの理解が既存の合意と違っていた場合は、その誤りを示して理解を訂正する。条件自体の変更が必要な場合は、衝突の内容と選択肢を示して相談し、合意なしに変更しない。

## 結果の示し方

確認対象を短く示し、次の列を持つ表にまとめる。

- 分類：ゴール・必須目標・努力目標・制約条件。
- 現在の理解：把握している内容。複数項目があれば行を分ける。
- 根拠・確かさ：根拠となる発言や文書と、明示・合意済み、推測、未確定などの状態。文書は参照箇所へのリンクを添える。

4分類をすべて示し、該当項目がないと確認できた場合は「なし」、情報が足りない場合は「未確認」と書き分ける。

表の下には、該当するものだけを簡潔に示す。

- 現在の作業とのずれ：どの作業が、どの条件と合っていないか。
- 完了に必要な残作業：未達の必須目標と必要な検証。完了を判断するための情報が不足する場合は、その点も示す。
- 確認したい点：ユーザーの回答によって作業判断が変わる質問と、その判断への影響。

## 終了と結果の扱い

- 現在の理解を整理し、作業判断に影響するずれや不明点が解消したら、このスキルによる確認を終える。重要な不明点がなければ、終了のためだけに承認を求めない。
- 人間の判断待ちなら、その点を示して回答を待つ。回答に依存する作業は進めない。今の判断に不要な未確定事項は、未確定のまま残す。
- 結果は標準ではチャット内に表示する。文書への保存や登録済みゴールの開始・更新などは、別途指示された場合に行う。確認の依頼だけでゴールの状態を変更しない。
- このスキルの終了と元の作業の完了を区別する。元の作業を継続するかどうかは、既に受けている依頼と確認結果に従う。
