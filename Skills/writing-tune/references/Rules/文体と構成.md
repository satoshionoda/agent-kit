# 基本の文体

- 残す文章は、簡潔で淡々とした常体を基本にする。明示された文体や参考文面がある場合は、それに従う。
- メールなど相手へ直接送る文章は、宛先・関係性・媒体に応じて敬体や丁寧調を使う。
- 感情の圧が強い言い回しや芝居がかった強調を避け、内容を直接伝える。正式な文章でも、必要以上に硬い言い回しへ寄せない。

# 情報量と構成を選ぶ

- 読み手が何を理解・判断・実行するための文章かと、既に知っていることを踏まえ、内容と詳しさを選ぶ。概要を知る文章と、操作や計算を再現する文章では、必要な説明が異なる。
- 冒頭は問いや現在地、大きな結論をつかめる分量にし、細かな内訳や用語は理解に必要になる位置へ置く。
- 見出しは、その節の対象や問いを具体的に示す。短い内容に見出しや分類を増やさず、全項目を埋めるための説明を足さない。
- 本文には、中心となる答え、その理由、結論を左右する条件を残す。詳しい根拠や追加の例は補足へ分けられるが、目的に不要な情報は補足へ移すだけでなく省く。
- 例や用語の説明は、理解や判断に必要なものを選ぶ。既出の例で説明を追えるなら活用し、数をそろえるために追加しない。

# 文章の性格に応じた書き方

以下の指針は、文章に含まれる内容に応じて組み合わせる。文書全体の目的から構成を決め、各部分ではその役割に合う書き方を使う。

## 進捗や状況を共有する

- 冒頭で現在地と大きな残作業を短く伝える。詳細に入る前に、どこまで進み、何が残っているかを示す。
- 完了、残る確認・反映、保留・別途対応など、状態ごとに見出しを分ける。実際に含まれる内容に合わせて見出しを選ぶ。
- 各項目は簡潔な箇条書きにし、実施内容と結果の関係が分かるように書く。理由や運用上の補足は、必要な箇所に短い段落で添える。
- 次の対応や判断が必要な事項は、その内容と条件を明記する。担当や時期が決まっていれば併記する。
- 実装や設定の詳細は、現在の状態や次の対応を理解するために必要な範囲で補足する。

## 手順や判断基準を示す

- 操作の前提や、その方法で目的を達成できる理由を、短い段落で説明する。具体的な操作と、設定を選ぶための判断基準を続けて示す。
- 作業や判断の単位で情報を整理する。順序が重要な手順には番号付きリスト、並列の条件や確認項目には箇条書きを使う。
- コマンドや設定例には、対象に合わせて変える箇所と、その選び方を添える。
- 必須・任意・推奨を、意味に応じて書き分ける。適用条件や注意事項は、対応する操作や判断の近くに置く。
- 主な方法と結果の確認方法を先に示し、補足や代替手段は分けて説明する。代替手段の制約も併記する。

## 仕組みや考え方を説明する

- 読み手の疑問に沿って、前提、仕組み、理由、具体的な対応へと説明を進める。内容を理解しやすい順序を選ぶ。
- 短い段落で、要素同士の関係や因果関係をつなぐ。仕組みと原因、対処とその効果を、読み手が補わずに理解できるようにする。
- 見出しで論点を区切り、条件・選択肢・確認項目など、並列に把握したい内容を箇条書きにする。
- 用語や具体例は、理解を助ける範囲で補う。既知の説明を重ねるより、その文脈で何を意味するかを示す。
- 主な説明を先に置き、補足や別の考え方は分けて示す。

## 構想や検討内容を残す

- 短い文や断片を使い、階層化した箇条書きを基本にする。
- 上位の項目に論点や考えのまとまりを置き、その下に理由・条件・具体例・懸念を整理する。
- 決まったこと、仮説、候補、未確定の論点を区別する。
- 複数案は同じ階層に並べ、各案の違いや判断材料をその下に置く。
- 読み物として整えるより、考えの関係と検討中の箇所が一目で分かることを優先する。文章を整えるために結論を補わない。

# 参照情報の置き方

- リンクや補足情報は、本文の流れを妨げない位置に置く。文中に入れると長くなる場合は、項目末尾や別の行に分ける。
- リンクの表示名は、参照先を識別できる範囲で短くする。
- 本文だけでも要点が分かるようにし、詳細や根拠を参照先で確認できる形にする。
