# Ubiquitous Language

## Overview

現在の会話や指定資料から、ドメインエキスパートと確認するためのユビキタス言語ドラフトを作成する。
出力は確定仕様ではなく、曖昧さを可視化し、次の確認会話を進めやすくするためのたたき台として扱う。

## Workflow

1. 会話と指定資料を確認し、ドメインに関係する名詞、動詞、状態、イベント、役割、ライフサイクルを拾い出す。
2. 既存の `UBIQUITOUS_LANGUAGE.md` がある場合は最初に読み、上書きではなく統合対象として扱う。
3. 同じ言葉が異なる概念に使われている箇所、異なる言葉が同じ概念に使われている箇所、曖昧または多義的な用語を特定する。
4. 採用する標準用語を方針を持って選び、避けるべき別名と実際に使われている呼称を分けて記録する。
5. 定義が不足している用語や、会話だけでは断定できない関係は `要確認` として残す。
6. 用語を自然なまとまりごとに分類し、`UBIQUITOUS_LANGUAGE.md` に書き込む。
7. 会話内では、追加・変更した用語、指摘した曖昧さ、次に確認すべき論点を簡潔に要約する。

## Output Format

`UBIQUITOUS_LANGUAGE.md` は次の構造を基本にする。
ドメインに自然なまとまりが複数ある場合は、見出しと表を増やす。

```md
# Ubiquitous Language

## <用語グループ名>

| 採用語 | 定義 | 避けるべき別名 | 実際の呼称 | 状態 |
| ------ | ---- | -------------- | ---------- | ---- |
| **注文** | 顧客が 1 つ以上の商品を購入するための依頼 | 購入、取引 | order | 確認済み |
| **請求書** | 納品後に顧客へ送られる支払い要求 | 請求、支払い依頼 | invoice | 要確認 |

## 関係

- **請求書** は、ちょうど 1 つの **顧客** に属する
- **注文** は、1 つ以上の **請求書** を生み出す
- **請求書** の生成条件は **注文** ではなく **フルフィルメント** に結びつく可能性がある `要確認`

## 会話例

> **開発者:** 「**顧客** が **注文** したとき、すぐに **請求書** を作成しますか？」
> **ドメインエキスパート:** 「いいえ。**請求書** は **フルフィルメント** が確認された後にだけ生成されます。」
> **開発者:** 「では、1 つの **注文** から複数の **請求書** が作られることがありますか？」
> **ドメインエキスパート:** 「あります。商品が別々の **出荷** に分かれる場合です。」

## 指摘された曖昧さ

- 「アカウント」は **顧客** と **ユーザー** の両方を指す意味で使われていた。**顧客** は注文を行う主体、**ユーザー** は認証主体として分けることを推奨する。

## 要確認

- **請求書** が生成される正確なタイミング
- **出荷** がキャンセルされた場合に **請求書** が存在するか
```

## Rules

- 採用語を決める。複数の候補語がある場合は最も適切なものを選び、他の語は `避けるべき別名` に入れる。
- 現場で使われているが標準語として採用しない呼称は、削除せず `実際の呼称` に残す。
- 会話内の推測、言い間違い、未確認の業務ルールを確定事項として書かない。
- ドメインエキスパートに関係する用語だけを含める。モジュール名、クラス名、関数名は、ドメイン言語として意味を持つ場合だけ含める。
- 定義は 1 文以内にする。その用語が何であるかを定義し、何をするかだけで説明しない。
- 一般的なプログラミング概念は、ドメイン固有の意味を持つ場合を除いて含めない。
- 関係では用語名を太字にし、明らかな場合は多重度や生成条件を書く。
- 曖昧さは `指摘された曖昧さ` に明示し、推奨する分け方を書く。
- 断定できない点は `要確認` に残し、確認相手や確認観点が分かる形にする。
- 会話例は 3-5 往復にし、関連する概念の境界が自然に分かる内容にする。

## Re-running

同じ会話や同じ作業ディレクトリで再実行する場合は、次のように進める。

1. 既存の `UBIQUITOUS_LANGUAGE.md` を読む。
2. その後の議論や指定資料から新しい用語を追加する。
3. 理解が変わった定義、関係、曖昧さを更新する。
4. 削除したい用語がある場合も、会話から消えただけでは削除せず、削除理由が明確なときだけ整理する。
5. 会話例を、最新の採用語と重要な境界を示す内容に書き直す。
